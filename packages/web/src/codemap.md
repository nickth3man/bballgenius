# packages/web/src/

## Responsibility

Root of the TanStack Start SPA. Defines the router, root HTML shell + layout shell, all file-based route pages/components, shared query client, and global Tailwind theme. This is the single entry point for the browser UI — every page, API handler, and UI component is wired from this folder.

## Design

### Router setup (`router.tsx`)

Creates a `TanStackRouter` via `createTanStackRouter()` from the auto-generated `routeTree` (imported from `routeTree.gen.ts`). Key configuration:

- **`RouteTree`** — Auto-generated by TanStack Start codegen; scans `routes/` recursively and builds a `Route` tree with `__root.tsx` as parent.
- **`context`** — Injects `QueryClient` into all route contexts via `RouterContext`.
- **`defaultPreload: 'intent'`** — Preloads route data on link hover/touch.
- **`scrollRestoration: true`** — Restores scroll position on back/forward navigation.
- **`Wrap`** — Wraps every route render with `<QueryClientProvider>` so `useQuery` works across all pages.
- **Type registration** — Declares `@tanstack/react-router` module augmentation for router type safety.

### Generated route tree (`routeTree.gen.ts`)

Auto-generated file (do not edit). Imports every file-based route, calls `.update({ id, path, getParentRoute })`, and assembles a single tree rooted at `__rootRoute` with six child routes. Exports `FileRoutesByFullPath`, `FileRoutesByTo`, `FileRoutesById`, and `FileRouteTypes` for type-safe routing. The `routeTree` constant is the default export consumed by `router.tsx`. Also declares `@tanstack/react-start` module augmentation with `ssr: true` and the router type.

### Root shell + layout (`routes/__root.tsx`)

Uses `createRootRouteWithContext<RouterContext>()` (typed with `QueryClient`). Two render slots:

- **`shellComponent: RootDocument`** — The outer `<html><head><HeadContent /></head><body>` wrapper with `<Scripts />`. Renders once per full-page load, not on client-side navigations.
- **`component: RootLayout`** — Persistent layout rendered on every navigation:
  - Header: brand wordmark (`BBallGenius`) + nav bar with four `<Link>` tabs (`Game Center`, `Career Time-Machine`, `SQL Sandbox`, `Chat`). Active tab highlighted via `data-[status=active]` pseudo-class. Disabled links use `opacity-40` + `cursor-not-allowed`.
  - `<Outlet />` — Route page component renders here.
  - Footer: static credit line (`nba.duckdb · DuckDB + TanStack Start`).

The `TABS` array is a hardcoded `const` — route metadata (label, path, enabled) is not data-driven.

### Route pages (`routes/`)

Six routes total (see child `routes/codemap.md`):

| Path | Module | Type |
|------|--------|------|
| `/` | `index.tsx` | Redirect → `/game-center` (via `beforeLoad` + `throw redirect()`) |
| `/game-center` | `game-center.tsx` | Page: recent games list + box score + shot chart |
| `/time-machine` | `time-machine.tsx` | Page: player search + career stats + awards |
| `/sql-sandbox` | `sql-sandbox.tsx` | Page: freeform SQL editor + schema tree + results table |
| `/chat` | `chat.tsx` | Page: chat UI posting to `/api/copilotkit` |
| `/api/copilotkit` | `api/copilotkit.ts` | Server-only POST handler bridging chat → LangGraph agent |

**Patterns across page routes:**

- **Server functions** — DuckDB access uses `createServerFn({ method: 'GET' | 'POST' })` with dynamic `import('data')` inside `.handler()`. This keeps SQL and DuckDB bindings server-only.
- **Client state** — `game-center.tsx` uses `@tanstack/react-query` (`useQuery` with `queryKey`). `time-machine.tsx` and `sql-sandbox.tsx` use manual `useState`/`useCallback`. `chat.tsx` uses plain `useState` + `fetch`.
- **API route** — `api/copilotkit.ts` uses `server.handlers.POST` (TanStack Start server-only pattern). Dynamically imports `@langchain/core/messages` and `data/tabs/chatbot/agent` to avoid Vite CJS-ESM conflicts.

### Shared components (`components/`)

Shared web-owned UI lives under `components/` (see child `components/codemap.md`):
- `CodeEditor`, `SchemaTree`, `ResultsTable` — SQL Sandbox primitives.
- `shotChart/` — half-court SVG geometry and dual shot chart.
- `timeMachine/player-dossier.tsx` — Career Time-Machine dossier sections.
- `ui/` — local BBallGenius primitives (`Button`, `Badge`, `Card`, `Tabs`, `StatTile`, `TeamCrest`, `Skeleton`).

All are inert presentational components with no server/DB access.

### Global styles (`styles/app.css`)

- Tailwind v4 (`@import 'tailwindcss'` + `@theme` block).
- Local BBallGenius broadcast theme variables: ink/paper surfaces, jersey blue, court orange, hardwood gold, semantic made/missed/status colors, type scale, spacing, radii, shadows, and motion.
- HTML/body reset: full-height dark canvas, Archivo body font, Saira display numerals, JetBrains Mono tables/SQL.

## Flow

```
bun run web (TanStack Start dev server)
  │
  └─ router.tsx creates TanStackRouter
       │
       ├─ route = routeTree.gen.ts (auto-generated)
       │   └─ __root (routes/__root.tsx)
       │       ├── /           → index.tsx       (redirect → /game-center)
       │       ├── /game-center  → game-center.tsx
       │       ├── /time-machine → time-machine.tsx
       │       ├── /sql-sandbox  → sql-sandbox.tsx
       │       ├── /chat         → chat.tsx
       │       └── /api/copilotkit → api/copilotkit.ts (server handler)
       │
       └─ context = { queryClient }
           └─ Wrap = <QueryClientProvider>
```

**Client-side navigation flow:**

```
Browser URL change
  → TanStack Router matches route
  → RootDocument shell   (html/head/body — full load only)
  → RootLayout renders    (header + outlet + footer)
  → Route component renders in <Outlet />
    → On mount: calls createServerFn (dynamic import from data package)
      → DuckDB query (read-only, via resolveDbPath())
    → User interactions → additional server fn calls
```

**Chat API flow:**

```
Chat page POST /api/copilotkit { messages: [{role, content}] }
  → api/copilotkit.ts server handler
    → Dynamic import @langchain/core/messages + data/tabs/chatbot/agent
    → toBaseMessages() → HumanMessage[] / AIMessage[]
    → streamQuery(baseMessages, freshThreadId)
      → token events → accumulate
      → done event → extract final assistant message
      → error event → short-circuit
    → Response.json({ messages: [{ role: "assistant", content }] })
```

## Integration

### Package boundary

This folder is the **sole UI entry point** of the BBallGenius monorepo. It imports from the `data` workspace package but never vice versa. All DuckDB access flows through `createServerFn` handlers that dynamically `import('data')` at runtime — no direct `packages/data/src/` relative imports.

### Data workspace (`packages/data`)

- **`data`** (default export) — `initDb()` + `query()` for raw DuckDB access. Used by `game-center.tsx`, `time-machine.tsx`, and `sql-sandbox.tsx`.
- **`data/tabs/time-machine/queries`** — Schema-aware `loadCareerStats()` + `loadPlayerAwards()`. Used only by `time-machine.tsx`.
- **`data/formatters`** — `formatTable()` for ASCII table rendering (career stats display) + `stripAnsi()` for client-side post-processing.
- **`data/tabs/chatbot/agent`** — `streamQuery()` async generator. Used only by `api/copilotkit.ts`.

### QueryClient / TanStack Query

Shared `QueryClient` (30s `staleTime`) created in `router.tsx`, injected via Router `context` + `QueryClientProvider` wrap. Available to all route components via `useQuery()`. Only `game-center.tsx` uses it explicitly today; other routes manage state manually.

### Environment variables

Routes that call DuckDB resolve the database path via `resolveDbPath()`, which reads `NBA_DUCKDB_PATH` env var or falls back to `data/nba.duckdb` (or `data/fixtures/nba.ci.duckdb` under CI). The chat API additionally requires `OPENROUTER_API_KEY`. See `packages/data/src/shared/dbPath.ts`.

### No CopilotKit front-end runtime

Despite the file name `api/copilotkit.ts`, the chat page (`chat.tsx`) uses a plain `fetch` POST and renders messages manually. The `@copilotkit/react-core` and `@copilotkit/react-ui` packages are **not** wired in this codebase.
