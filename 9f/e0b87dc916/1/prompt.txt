</goal>

<context>

<target_qualities>
- Modular: split the UI into small, single-responsibility components/modules with clear
  inputs and boundaries; remove duplicated markup and logic.
- Extensible: structure it so a new UI element or feature can be added by adding code
  rather than rewriting existing components; expose clear extension points (props,
  slots, config, etc.).
- Editable: make it easy for a developer to find and change things — descriptive names,
  separation of structure / styling / logic / data, and configuration or content lifted
  out of hard-coded markup.
</target_qualities>

<instructions>
Work in this order:
1. Briefly assess the current structure and name the 3–5 issues most responsible for it
   being hard to edit, extend, or reuse.
2. Propose a refactoring plan: the target component/module breakdown and what moves where.
3. Implement the refactor, presenting the result as complete files or clearly labeled
   modules — not fragments.
4. Note anything a reviewer should check to confirm behavior is unchanged.

If a meaningfully better structure would require a small behavior change, flag it rather
than making it silently.
</instructions>

<success_criteria>
A correct result has: identical behavior and appearance; clear single-responsibility
modules; no duplicated UI logic; and a structure where adding a new component or feature
is visibly simpler than before.
